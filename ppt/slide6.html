Saving attendance — no silent overwrites

The save transaction

1

Authorize: teacher owns the course, rate limit OK

2

Optimistic lock: UPDATE session SET version = version + 1 WHERE id = ? AND version = ?

3

Match: upsert attendance records + audit event, commit

4

Respond: canonical session + new version returned from the primary

When it fails, it fails loudly

Version mismatch → 409. Another device saved first. The teacher's marks stay on screen; they reload and re-apply.

Network failure → nothing cleared. Unsaved marks are preserved in the browser; a retry is offered.

Every save is audited — actor, before/after values, and request IP land in audit_events.
